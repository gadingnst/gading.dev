Gw awalnya mikir bikin AI Agent itu gampang. Tinggal panggil LLM, suruh dia nge-output JSON, parsing hasilnya, panggil tool Python yang sesuai, kelar.

Tapi begitu agen yang gw rancang butuh logika yang lebih kompleks (misalnya harus ada perulangan (*loops*) di mana agen nyoba suatu tugas, ngecek hasilnya, dan kalau salah dia harus benerin kodenya sendiri sebelum nanya ke gw), script Python gw mulai berubah jadi sarang laba-laba (*spaghetti code*).

Gw nyoba nulis *state manager* sendiri. Ngirim list `messages` bolak-balik lewat argumen fungsi, nge-handle error tool call secara manual, sampai nyoba nge-jeda eksekusi buat nunggu persetujuan gw (*human-in-the-loop*). Hasilnya? Pusing sendiri. Kodenya jadi rapuh, susah di-debug, dan rawan kena *infinite loop* yang bikin kuota API key gw ludes dalam semalam.

Di sinilah gw nabrak batasan LangChain biasa dan mutusin buat migrasi ke **LangGraph**.

Awalnya gw skeptis, *"Ah, paling ini cuma wrapper LangChain lainnya yang bikin ribet."* Tapi setelah gw coba refaktor logic asisten gw (Nouva) pake library ini, gw sadar konsep graf berbasis *state* yang mereka tawarin itu solusi paling masuk akal buat masalah gw.

### Konsep Inti LangGraph (Bukan Teori Kaku)

LangGraph itu gampangnya cuma metain alur kerja agen lu jadi diagram alur (graf) yang punya memori bersama (*state*). Ada tiga komponen utama yang wajib lu pahamin:

1.  **State (Buku Catatan Bersama)**: Ini sumber kebenaran tunggal (*single source of truth*) buat graf lu. Bayangin kayak buku catatan yang dioper dari satu meja ke meja lain. Semua data percakapan, hasil tool, dan variabel global disimpen di sini. Tiap langkah (node) bisa baca dan nulis ke buku catatan ini.
2.  **Nodes (Para Pekerja)**: Ini cuma fungsi Python biasa yang ngerjain tugas spesifik. Satu node tugasnya cuma manggil LLM, node lain nge-run query database, node lainnya lagi nge-run tool. Node nerima `State` saat ini, kerja, terus balikin perubahan (*update*) buat ditulis ke `State`.
3.  **Edges (Alur Antrean)**: Ini garis penghubung antar node yang nentuin buku catatan tadi dioper ke mana berikutnya.
    *   **Normal Edges**: Alur langsung (misal: setelah selesai manggil LLM, langsung oper ke node eksekusi tool).
    *   **Conditional Edges**: Alur bercabang berdasarkan kondisi tertentu (misal: cek catatan terakhir LLM. Kalau LLM minta panggil tool kalkulator, arahin ke node kalkulator. Kalau LLM udah selesai jawab, arahin ke node selesai).

### Praktek: Bikin Agen Pertama Lu

Sekarang bikin agen sederhana yang bisa ngelakuin operasi matematika dasar pake sebuah *tool*. Kalau user nanya soal matematika, agen bakal diarahin ke node tool kalkulator; kalau cuma ngobrol biasa, agen langsung jawab tanpa manggil tool.

#### 1. Persiapan

Install dulu library-nya. Di sini gw pake OpenAI sebagai LLM-nya:

```bash
pip install langgraph langchain-openai
```

#### 2. Rancang Buku Catatan (State)

Definisiin `AgentState` yang bakal ngelacak daftar pesan percakapan. Pake `add_messages` biar pesan baru otomatis ditambahin ke daftar lama, bukan nimpa.

```python:state.py
from typing import Annotated, Sequence
from typing_extensions import TypedDict
from langchain_core.messages import BaseMessage
from langgraph.graph.message import add_messages

class AgentState(TypedDict):
    # add_messages bertindak sebagai reducer untuk menggabungkan pesan baru
    messages: Annotated[Sequence[BaseMessage], add_messages]
```

#### 3. Setup Model dan Tool

Bikin satu tool sederhana namanya `multiply` buat ngaliin angka, terus sambungin tool ini ke model LLM.

```python:agent.py
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Mengalikan dua bilangan bulat."""
    return a * b

tools = [multiply]
# Kita bind tools ke model agar LLM tahu dia punya akses ke tool perkalian
model = ChatOpenAI(model="gpt-4o-mini", temperature=0).bind_tools(tools)
```

#### 4. Definisikan Nodes (Para Pekerja)

Butuh dua node: satu buat manggil LLM (`call_model`), satu lagi buat nge-run tool (`tool_node`). LangGraph udah nyediain `ToolNode` bawaan, jadi gak perlu nulis fungsi eksekusi tool manual.

```python:nodes.py
from langchain_core.messages import ToolMessage
from langgraph.prebuilt import ToolNode

# Node 1: Manggil LLM
def call_model(state: AgentState):
    messages = state["messages"]
    response = model.invoke(messages)
    # Kita kembalikan pesan respons LLM untuk diupdate ke State
    return {"messages": [response]}

# Node 2: Eksekutor Tool
tool_node = ToolNode(tools)
```

#### 5. Logika Percabangan (Conditional Edge)

Ini otak yang nentuin alurnya. Cek pesan terakhir dari LLM: LLM butuh manggil tool gak? Kalau iya, lanjut ke node `tools`. Kalau gak, stop workflow.

```python:routing.py
def should_continue(state: AgentState):
    last_message = state["messages"][-1]
    # Coba cek apakah ada tool_calls di respons terakhir LLM
    if last_message.tool_calls:
        return "tools"
    # Kalau gak ada, kita arahkan ke node spesial '__end__' untuk berhenti
    return "__end__"
```

#### 6. Satukan Semua di Graf

Sekarang rakit semuanya pake `StateGraph`. Di sini enaknya LangGraph kelihatan: alur kerja agen didefinisiin secara deklaratif dan gampang banget dibaca.

```python:graph.py
from langgraph.graph import StateGraph, START, END

# 1. Inisialisasi graf dengan State yang udah kita rancang
workflow = StateGraph(AgentState)

# 2. Daftarkan node-node pekerja kita
workflow.add_node("agent", call_model)
workflow.add_node("tools", tool_node)

# 3. Tentukan titik mulai (START) langsung masuk ke node agent
workflow.add_edge(START, "agent")

# 4. Tambahkan logika percabangan dari node agent
workflow.add_conditional_edges(
    "agent",
    should_continue,
    {
        # formatnya: "kondisi": "node tujuan"
        "tools": "tools",
        "__end__": END
    }
)

# 5. Setelah tool selesai dieksekusi, oper balik hasilnya ke node agent
# Ini yang disebut siklus (cycle/loop)
workflow.add_edge("tools", "agent")

# 6. Compile graf menjadi aplikasi siap pakai
app = workflow.compile()
```

#### 7. Uji Coba Agen Lu

Tes jalanin graf yang udah di-compile tadi:

```python:main.py
from langchain_core.messages import HumanMessage

# Kita coba kirim pertanyaan matematika yang butuh tool perkalian
events = app.stream(
    {"messages": [HumanMessage(content="Berapa hasil dari 23 dikali 45?")]}
)

for event in events:
    for value in event.values():
        print("Assistant:", value["messages"][-1].content)
```

### Kenapa Akhirnya Gw Suka LangGraph? (Trade-offs & Verdict)

Gw gak bakal bilang LangGraph itu library yang sempurna. *Learning curve*-nya lumayan bikin dahi mengkerut di awal, apalagi kalau lu gak biasa sama konsep Graph Theory atau sintaksis LangChain Expression Language (LCEL) yang kadang kerasa bertele-tele.

Tapi buat project agen yang kompleks, hasilnya sebanding sama repotnya belajar di awal:

*   **Loops Jadi First-Class Citizen**: Gak ada lagi drama nulis loop `while True` manual yang rawan *infinite loop*. Alur berputar (LLM -> Tool -> LLM) diurus graf secara native dan aman.
*   **Human-in-the-Loop Tanpa Ribet**: Ini fitur paling penting buat gw. Gw bisa gampang nge-pause eksekusi graf pas agen mau nge-run command sensitif (kayak nulis file atau hapus data), nunggu approval gw lewat chat, terus ngelanjutin graf dari state terakhirnya.
*   **Persistensi State Otomatis**: LangGraph punya *checkpointer* bawaan. State percakapan lu otomatis disimpen ke memori (atau database kayak Postgres/Sqlite) tanpa perlu lu simpen manual tiap ganti turn.

### Jadi, kapan pake LangGraph?

Kalau agen lu cuma butuh alur linear sekali jalan (tanya -> cari DB -> jawab), LangChain biasa atau script Python raw udah lebih dari cukup. Jangan over-engineer.

Tapi begitu agen lu butuh mikir berulang kali, pake tools secara dinamis, dan butuh pengawasan manusia sebelum ngejalanin perintah bahaya, **LangGraph** pilihan paling pragmatis saat ini biar lu gak kejebak di neraka *spaghetti code*.
